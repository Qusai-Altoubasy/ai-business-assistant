# AI Business Assistant

A small learning project that demonstrates a Quarkus REST API and a declarative LangChain4j AI service backed by the Gemini Developer API.

## Tech Stack

- Java 21
- Quarkus 3.39
- Quarkus LangChain4j
- Google Gemini
- Maven Wrapper

## Requirements

- JDK 21 or later
- A Gemini Developer API key for the AI-powered endpoint

Maven does not need to be installed because the project includes the Maven Wrapper.

## Getting Started

From the repository root:

```bash
cd Backend
cp .env.example .env
```

Replace the placeholder values in `.env` with your own Gemini API key and model ID. The `.env` file is ignored by Git.

## Configuration

The application reads these environment variables:

| Variable | Required | Description |
| --- | --- | --- |
| `GEMINI_API_KEY` | Yes | Gemini Developer API key |
| `GEMINI_MODEL` | Yes | Gemini chat model ID |

You can use a local `.env` file as described above, or export the variables in your shell:

```bash
export GEMINI_API_KEY="your-api-key"
export GEMINI_MODEL="gemini-3.6-flash"
```

Never commit a real API key.

## Running the Application

```bash
cd Backend
./mvnw quarkus:dev
```

Run the test suite with:

```bash
cd Backend
./mvnw clean test
```

## Example Request

The deterministic endpoint does not call Gemini:

```bash
curl http://localhost:8080/hello
```

```text
Hello World
```

The AI-powered endpoint returns a short greeting generated by Gemini:

```bash
curl http://localhost:8080/hello/ai/Quarkus
```

The exact response varies because it is generated by the model. Calling this endpoint sends the supplied name to Gemini and may incur API usage costs.

## Purpose

This repository is intentionally small. It shows how Quarkus generates an implementation for a LangChain4j AI service declared with `@RegisterAiService`, and how that service can be injected into a REST resource.
